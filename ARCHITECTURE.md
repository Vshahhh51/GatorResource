# GatorResource architecture

## Stack

Next.js App Router, React, TypeScript, and plain CSS. The user explicitly selected Next.js in place of the original Python/Streamlit plan.

## Request flow

1. `app/page.tsx` keeps search text and results in React memory. Replacing or clearing input aborts the current browser request and invalidates its result version.
2. `POST /api/match` limits request size and validates the description. Responses are marked `no-store`; the application does not log descriptions or model responses.
3. `lib/matching.ts` calls Gemini using a server-only ADC credentials and a configurable model. The official REST structured-output schema restricts resource IDs; local validation independently rejects bad structures, unknown IDs, external links, and more than three matches. Duplicates are removed.
4. The browser resolves resource IDs against `data/resources.json`. Links and next steps are never generated by Gemini. AI explanations are rendered as text, not HTML or Markdown.
5. The same directory supports category browsing without calling the API. Optional text downloads are generated locally.

## Trust and limitations

Prompt instructions separate untrusted student content from directory facts. Structural validation cannot prove semantic relevance or factual accuracy of AI explanations; those require live scenario testing and human review. Unknown availability and eligibility accompany every resource. Eight official sources were reviewed on 2026-10-02; there is no runtime crawling.

Gemini defaults to `gemini-3.8-flash`, listed in the Google model documentation when reviewed. Project-specific access is unverified until a successful live request. `GEMINI_MODEL` can change the model without a code edit.

## Deployment

Next.js standalone output is packaged in a multi-stage Docker image. The runtime uses the non-root Node user, binds `0.0.0.0`, and respects Cloud Run's `PORT`. Cloud Run uses its attached service account for ADC; `.env` files are excluded from Docker build context. `/api/health` checks the app process, not Gemini access.

No database, auth, vector store, or shared search cache is included. A public demo with a shared Google Cloud project needs a deliberate usage budget and deployment access policy; the current prototype has no distributed rate limiter.

## Vertex AI migration

Authentication uses google-auth-library ADC and Bearer authorization. The fixed global endpoint is https://aiplatform.googleapis.com/v1/projects/PROJECT/locations/global/publishers/google/models/MODEL:generateContent. Configure GOOGLE_CLOUD_PROJECT and GOOGLE_CLOUD_LOCATION=global. The model remains gemini-3.8-flash. Structured requests use responseMimeType and responseJsonSchema. No Gemini API key is used.
